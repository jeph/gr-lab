# BLE slice — shared findings so far (BleProtocol)

Working notes from the GR WORLD BLE analysis. Addresses refer to `work/dis/dis.txt` in the local research workspace (`../gr`); the helper `work/scratch/ble/h.py` there loads it (`d`, `cfunc`, `crange`, `fo`, `callers`, ...). Dart arm64 conventions: x27 = object pool, x21 = dispatch table, Smi = 2n, class id = `(tag >> 12)` via `ubfx x, x, #0xc, #0x14`.

## Method that works
- GATT characteristics are modelled as Dart classes (one class per characteristic). Each "family" (one per service) has an abstract base type and a builder function that allocates one instance of each subclass into a List.
- Finder functions take (device services, ..., List<family>) and pair each class with the FBP BluetoothCharacteristic (type `dpb`) by calling a virtual `uuid` getter (dispatch-table call `ldr x30,[x21, cid+SEL]`), producing HTb<Family, dpb> pairs.
- Code that wants one characteristic filters the pairs with a closure that compares the class id: e.g. closure 0x579158 does `cmp x1, #0x649` => kIb (Battery notify). So: **cid compare in closure/switch => which characteristic is used**.
- The `uuid` getters are tiny functions `add x0,x27,..; ldr x0,[x0,#off]; ret` laid out in blocks. Within a block, getters are in **descending class-id order** (validated: 7/7 service getters vs. finder literals; DIS block vs. firmware-version check that reads 2A24 model + 2A26 firmware). Use this rule; cite it as [inferred: getter-block order].
- FBP primitives: BluetoothCharacteristic.read = 0xd314d0 ("readCharacteristic"), write = 0xe5c094 ("writeCharacteristic", wrapper 0xe5bfb0), setNotifyValue = 0xd3469c, requestMtu 0xd33c6c, connect 0xd33764/0xd341e0, discoverServices 0xd427ec, createBond 0xda965c, getBondState 0xda6ee0, startScan 0xd45e7c. App generic read<T> helper = 0xd30588 (takes a per-characteristic decoder obtained via virtual selector -0xffe on the class). App BLE service class is `uFb` (cid 0x699, library qqn), provider "bleServiceProvider".
- Notify setup pattern (e.g. Battery 0xd35014): find pairs -> select class by cid closure -> 0x5788b4 + closure of parser class (e.g. EHb closure 0x579188 "onNotifyChanged, bytes: ") -> setNotifyValue(true) 0xd3469c -> initial read 0xd314d0. Error strings "XNotify error: ".
