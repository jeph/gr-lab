**GR Lab** คือแอปคู่หูสำหรับกล้อง Ricoh GR (GR III, GR IIIx และ GR IV) บน iOS และ Android ใช้เรียกดูและดาวน์โหลดภาพในกล้อง ใช้เป็นรีโมตชัตเตอร์พร้อมไลฟ์วิว และเก็บลุค “ควบคุมภาพ” ของคุณไว้ในที่เดียว แอปนี้สร้างขึ้นให้ทำงานเร็ว ใช้ง่าย และจัดการโปรไฟล์สีของกล้องได้อย่างจริงจัง ไม่ว่าจะเป็นการบันทึกลุคที่ใช้ถ่ายภาพ การแก้ไขลุคโดยดูพรีวิวประกอบ หรือการโหลดลุคลงช่องกำหนดเองของกล้อง

GR Lab เป็นโปรเจกต์อิสระ ไม่มีส่วนเกี่ยวข้องกับ Ricoh แอปสื่อสารกับกล้องด้วยโปรโตคอลที่ได้จากการทำวิศวกรรมย้อนกลับแอปของ Ricoh เองและเฟิร์มแวร์ของกล้อง สิ่งที่ค้นพบเขียนรวบรวมไว้ใน [`research/`](../../research/README.md)

## คุณสมบัติ

GR Lab ให้ความสำคัญกับสามเรื่องเป็นอันดับแรก ได้แก่ การเข้าถึงภาพของคุณได้อย่างรวดเร็ว การไม่เกะกะขวางทางคุณ และการมองว่าลุค “ควบคุมภาพ” เป็นสิ่งที่ควรค่าแก่การจัดการ

- **เร็ว** เมื่อเปิดแอป GR Lab จะเชื่อมต่อกับกล้องผ่านบลูทูธ หากกล้องอยู่ใกล้เคียง การเปิดคลังภาพจะปลุกกล้อง เปิด Wi-Fi ของกล้อง และเข้าร่วมเครือข่ายให้ในคราวเดียว จากนั้น Wi-Fi จะเปิดค้างไว้ขณะที่คุณสลับไปมาระหว่างหน้าต่างๆ จึงไม่ต้องเข้าร่วมซ้ำและการดาวน์โหลดก็ดำเนินต่อไปได้ รายการไฟล์ ภาพขนาดย่อ และภาพพรีวิวจะถูกแคชไว้ในโทรศัพท์ คลังภาพจึงเปิดได้เร็ว เมื่อใช้ GR IV HDF กับโทรศัพท์ Android กล้องที่ปิดอยู่ใช้เวลาประมาณ 13 วินาทีจนเปิดคลังภาพได้
- **ใช้ง่าย** กล้องทั้งหมดของคุณอยู่ในหน้าจอเดียว และแตะครั้งเดียวจากหน้านั้นก็ถึงคลังภาพ ถ่ายภาพ และลุค GR Lab จะเปิดกล้อง เปิด Wi-Fi ของกล้อง และเข้าร่วมเครือข่ายให้คุณเอง หลังจับคู่แล้วจึงไม่ต้องตั้งค่าอะไรบนกล้องอีก เมื่อมีอะไรล้มเหลว แอปจะบอกสาเหตุและสิ่งที่ควรตรวจสอบ พร้อมปุ่ม “ลองอีกครั้ง” การเชื่อมต่อที่หลุดจะกลับมาเอง
- **ลุคที่คุณจัดการได้** ภาพทุกภาพในคลังภาพจะแสดง “ควบคุมภาพ” ที่ใช้ถ่าย และแตะครั้งเดียวก็บันทึกเป็นลุคได้ ลุคจะเก็บอยู่ในโทรศัพท์ของคุณไม่ว่าจะมาจากกล้องตัวใด พร้อมการตั้งค่า ภาพต้นทางของลุค และป้ายกำกับบอกช่องกำหนดเองที่เก็บลุคนั้นอยู่
- **ตัวแก้ไขลุคพร้อมพรีวิว** เปลี่ยนภาพฐานและพารามิเตอร์ทุกตัวของภาพฐานนั้น ซึ่งจัดกลุ่มเป็น โทน สี รายละเอียด และเอฟเฟกต์ แล้วดูผลลัพธ์บนภาพของคุณเองหรือภาพตัวอย่าง โดยเลื่อนเส้นแบ่งระหว่างภาพก่อนและหลังปรับ วางเทียบคู่กัน หรือแตะเพื่อสลับ พรีวิวเป็นการประมาณผลการประมวลภาพของกล้อง ซึ่งวิเคราะห์มาจากเฟิร์มแวร์ของกล้อง ([`research/image-control-processing.md`](../../research/image-control-processing.md))
- **โหลดลุคลงกล้อง** หน้าลุคแสดงสิ่งที่อยู่ในช่องกำหนดเอง C1 ถึง C3 ของกล้อง ลากลุคที่บันทึกไว้ไปวางบนช่อง หรือเลือก “โหลด” จากเมนูของลุค แล้วลุคก็จะอยู่ในกล้อง การอ่านและการโหลดลงช่องทำได้ผ่านบลูทูธเพียงอย่างเดียว โดยไม่ต้องเข้าร่วม Wi-Fi ของกล้อง
- **คลังภาพ** เรียกดูภาพและวิดีโอในกล้องตามวัน กรองตาม JPEG, RAW, วิดีโอ หรือยังไม่ดาวน์โหลด และเปิดภาพใดก็ได้แบบเต็มหน้าจอพร้อมรายละเอียด ดาวน์โหลดทีละภาพหรือหลายภาพที่เลือกไว้ เป็น JPEG, RAW หรือทั้งสองแบบ ลงในอัลบั้ม GR Lab ในคลังรูปภาพของโทรศัพท์ ส่วนวิดีโอเล่นได้ในแอป
- **รีโมตชัตเตอร์** ปุ่มชัตเตอร์ขนาดใหญ่ที่ทำงานผ่านบลูทูธเพียงอย่างเดียว พร้อมตั้งเวลาถ่ายภาพ โหมดขับเคลื่อน แป้นหมุนเลือกโหมด จำนวนภาพที่ถ่ายได้อีก และแบตเตอรี่ บน Android ปุ่มปรับเสียงก็ใช้ลั่นชัตเตอร์ได้เช่นกัน
- **ไลฟ์วิว** ภาพจากกล้องผ่าน Wi-Fi แตะเพื่อโฟกัส ตั้งรูรับแสง ความเร็วชัตเตอร์ ISO และการชดเชยแสงด้วยวงแหวนที่แสดงค่าที่กล้องมีให้เลือก และเปลี่ยนโหมดขับเคลื่อน ตั้งเวลาถ่ายภาพ วัดแสง และ “ควบคุมภาพ” ได้
- **กล้องหลายตัว** จับคู่ได้ครบทุกตัวที่คุณมีและสลับไปมาระหว่างกล้องได้ เปลี่ยนชื่อหรือเลิกจำกล้องแต่ละตัวได้
- **ธีมและภาษา** ธีมสว่าง มืด ห้องมืด กระดาษ และไซยาโนไทป์ และ 21 ภาษาเดียวกับเมนูของตัวกล้อง
- **เป็นส่วนตัว** ไม่มีบัญชีผู้ใช้ การเก็บข้อมูลวิเคราะห์ โฆษณา หรือการรายงานข้อขัดข้อง GR Lab สื่อสารกับกล้องของคุณเท่านั้น ดูได้ที่[นโยบายความเป็นส่วนตัว](../../app/assets/privacy.md)

## ข้อกำหนด

- กล้อง Ricoh GR III, GR IIIx หรือ GR IV รวมถึงรุ่น HDF และ GR IV Monochrome
- ลุคต้องใช้ GR IV ที่มีเฟิร์มแวร์ 1.04 ขึ้นไป, GR IV HDF หรือ GR IV Monochrome เฟิร์มแวร์ของ GR III และ GR IIIx ไม่มีช่องทางให้อ่านหรือเขียนการตั้งค่า “ควบคุมภาพ” จากโทรศัพท์
- Android 12 ขึ้นไป หรือ iOS 15 ขึ้นไป

GR Lab ยังเป็นแอปใหม่ บันทึกการทดสอบกับฮาร์ดแวร์มีการทดสอบกับ GR IV HDF ที่ใช้เฟิร์มแวร์ 1.20 ได้แก่ การจับคู่ การเชื่อมต่อ การปลุกกล้อง การเรียกดู การดาวน์โหลด ไลฟ์วิว การโฟกัส และการเปลี่ยนค่าการรับแสง การรองรับ GR III และ GR IIIx อาศัยผลการวิจัยโปรโตคอล และยังไม่ได้ทดสอบกับกล้องจริง ดูสิ่งที่สังเกตพบแล้วได้ที่ [`research/hardware-validation.md`](../../research/hardware-validation.md)

## การติดตั้ง

ตอนนี้ยังไม่มีรุ่นที่แพ็กเกจไว้ให้ จึงต้องติดตั้ง GR Lab ด้วยการบิลด์จากซอร์สโค้ด การบิลด์ต้องใช้ [Flutter](https://flutter.dev) 3.47 ขึ้นไป และตั้งค่า Android SDK หรือ Xcode ไว้แล้ว

```sh
git clone https://github.com/jeph/gr-lab.git
cd gr-lab/app
flutter run --flavor prod --release
```

`flutter run` จะติดตั้งแอปลงในโทรศัพท์ที่เชื่อมต่ออยู่กับคอมพิวเตอร์ของคุณ การบิลด์สำหรับ iOS ต้องใช้ทีมสำหรับเซ็นโค้ดของคุณเองที่มีความสามารถ Hotspot Configuration และ Access Wi-Fi Information

หากต้องการลองใช้แอปโดยไม่มีกล้อง ให้รันในโหมดสาธิต ซึ่งใช้ GR IV จำลองพร้อมภาพตัวอย่าง และใช้ได้บน Android emulator และ iOS simulator:

```sh
flutter run --dart-define=GR_DEMO=true
```

## การใช้งาน

1. **จับคู่กล้อง** แตะ “เพิ่มกล้อง” แล้วทำตามคำแนะนำ บนกล้อง การจับคู่อยู่ที่ MENU, E6, ตั้งค่าการสื่อสารไร้สาย ให้ตั้ง “โหมดแอคชั่น” เป็น “เปิด” เปิด “จับคู่” แล้วเลือก “ทำการจับคู่” จากนั้นยืนยันรหัสบนโทรศัพท์ แล้วกด OK บนกล้อง กล้องจะปรากฏในหน้าจอ “กล้อง” และ GR Lab จะเชื่อมต่อกับกล้องเองเมื่อเปิดแอปขณะที่กล้องอยู่ใกล้เคียง
2. **เปิดคลังภาพ** GR Lab จะเปิดกล้องหากกล้องปิดอยู่ และเข้าร่วม Wi-Fi ของกล้อง Android จะขอให้คุณอนุมัติเครือข่ายของกล้องหนึ่งครั้ง แตะภาพเพื่อดู แตะค้างไว้เพื่อเลือกหลายภาพ แล้วดาวน์โหลดภาพที่ต้องการเก็บ
3. **ถ่ายภาพ** “รีโมต” คือชัตเตอร์ผ่านบลูทูธ ส่วน “ไลฟ์วิว” จะเข้าร่วม Wi-Fi ของกล้องและแสดงภาพจากกล้อง พร้อมตัวควบคุมโฟกัสและการรับแสง
4. **บันทึกลุค** เปิดภาพในคลังภาพแล้วแตะ “บันทึกลุค” หรือสร้างลุคใหม่ตั้งแต่ต้นด้วย + ในหน้าลุค แตะลุคเพื่อแก้ไข แล้วลากไปวางบน C1, C2 หรือ C3 เพื่อโหลดลงกล้อง

“ตัดการเชื่อมต่ออัตโนมัติ” ใน “การตั้งค่า” จะออกจาก Wi-Fi ของกล้องเมื่อไม่ได้ใช้ GR Lab ไประยะหนึ่ง (ค่าเริ่มต้นคือ 5 นาที) [GR Lab ทำงานอย่างไร](../behaviour.md) อธิบายหน้าจอแต่ละหน้าและสถานะการเชื่อมต่อทุกแบบไว้อย่างละเอียด

## การพัฒนา

### โครงสร้าง

| พาธ | เนื้อหา |
|---|---|
| `packages/gr_protocol` | BLE GATT, HTTP API ผ่าน Wi-Fi, WebSocket แจ้งการเปลี่ยนแปลง และเซสชันเชื่อมต่อ/กู้คืน เขียนด้วย Dart ล้วน |
| `packages/gr_camera` | เลเยอร์กล้องที่แอปเรียกใช้สำหรับทุกอย่างที่เกี่ยวกับกล้อง ได้แก่ อะแดปเตอร์บลูทูธและ Wi-Fi (พร้อมโค้ด Kotlin และ Swift สำหรับเข้าร่วม Wi-Fi) เซสชัน การจับคู่ การสแกน คลังภาพ ถ่ายภาพ และไลฟ์วิว รวมถึงการบันทึกร่องรอยของการรับส่งข้อมูลทุกครั้ง |
| `packages/gr_fake_camera` | GR IV จำลอง (BLE, การเข้าร่วม Wi-Fi, เซิร์ฟเวอร์ HTTP บน loopback) สำหรับการทดสอบและโหมดสาธิต |
| `app` | แอป Flutter พร้อมโค้ด Kotlin และ Swift สำหรับบันทึกลงคลังรูปภาพ |
| `research` | งานวิจัยโปรโตคอล: วิธีค้นพบแต่ละ route และ characteristic หลักฐานจากเฟิร์มแวร์ ผลการทดสอบกับฮาร์ดแวร์ และคำถามที่ยังไม่มีคำตอบ |
| `tool` | `check.sh` การตรวจสอบคุณภาพโค้ดทั้งหมด และ `testflight.sh` การอัปโหลดสำหรับ iOS |

### การรัน

```sh
cd app
flutter run                                  # บิลด์ dev กับกล้องจริง (ต้องใช้โทรศัพท์ที่มีบลูทูธ)
flutter run --profile                        # เหมือนกัน แต่เร็วเท่าบิลด์ release
flutter run --flavor prod --release          # บิลด์ที่ผู้ใช้ได้รับ
flutter run --dart-define=GR_DEMO=true       # กล้องจำลอง ใช้ได้บน Android emulator และ iOS simulator
```

บิลด์มีสองแบบ `dev` (`io.jeph.grlab.dev` ชื่อ "GR Lab Dev") ติดตั้งคู่กับ `prod` (`io.jeph.grlab`, "GR Lab") ได้ หากไม่ระบุ `--flavor` คำสั่ง `flutter run` และ `flutter build` จะบิลด์ `dev`

`flutter run` เพียงอย่างเดียวจะสร้างบิลด์ debug ซึ่งสร้างแต่ละเฟรมช้ากว่าบิลด์ profile หรือ release หลายเท่า (3 ถึง 4 เท่าในคลังภาพบน Android emulator เมื่อ 2026-11-10) ให้ประเมินความลื่นไหลของหน้าจอด้วย `--profile` หรือ `--release`

โหมดสาธิตเก็บข้อมูลไว้ในโฟลเดอร์ `demo/` แยกต่างหาก ในการเปิดครั้งแรก “เพิ่มกล้อง” จะพบกล้องจำลอง และกล้องจะยืนยันการจับคู่เอง การเปิดครั้งต่อๆ ไปจะเริ่มโดยที่กล้องปิดอยู่ และจะปิดอยู่อย่างนั้นจนกว่าคุณจะเปิดคลังภาพ (การปลุกกล้องเป็นส่วนหนึ่งของการเข้าร่วม Wi-Fi ของกล้อง) หรือกดปุ่มเปิด/ปิดบนการ์ด ไฟล์ RAW ของโหมดสาธิตคือข้อมูล JPEG ที่ตั้งชื่อเป็น `.DNG`

### การตรวจสอบ

```sh
tool/check.sh            # ตัวจัดรูปแบบ ตัววิเคราะห์ ขอบเขตของเลเยอร์กล้อง คำแปล และชุดทดสอบทั้งหมด
tool/check.sh --static   # ไม่รวมการทดสอบ
```

ตัววิเคราะห์ใช้ `very_good_analysis` โดยถือว่า info เป็นข้อผิดพลาด การบิลด์ Android และ iOS จะรัน `tool/check.sh --static` ก่อน และหยุดหากไม่ผ่าน คำเตือนของ Kotlin และ Swift ถือเป็นข้อผิดพลาด ดูกฎได้ที่ [`AGENTS.md`](../../AGENTS.md)

### การทดสอบ

```sh
(cd packages/gr_protocol && dart test)
(cd packages/gr_fake_camera && dart test)
(cd packages/gr_camera && flutter test)
(cd app && flutter test)
(cd app && flutter build apk --debug --flavor dev --dart-define=GR_DEMO=true)
(cd app && flutter test integration_test --flavor dev --dart-define=GR_DEMO=true -d <device>)
```

การทดสอบแบบ integration จะรันขั้นตอนของโหมดสาธิตทั้งหมด (จับคู่ เชื่อมต่อ เรียกดู ดาวน์โหลดสองภาพ) บนอุปกรณ์จริง emulator หรือ simulator บิลด์ debug ต้องการพื้นที่ว่างประมาณ 400 MB บน emulator บน Android คำสั่ง `flutter test` ไม่ได้นำ flavor เริ่มต้นหรือ ID ของแอปมาจากโปรเจกต์ จึงต้องระบุ `--flavor dev` และต้องมี APK ที่บิลด์ไว้ล่วงหน้า หากไม่มี คำสั่งจะหยุดพร้อมข้อความ "No application found"

บน iOS simulator แอปต้องติดตั้งอยู่แล้วในตอนที่ให้สิทธิ์เข้าถึงรูปภาพ และ `flutter test` จะถอนการติดตั้งแอปหลังทดสอบเสร็จ ซึ่งทำให้สิทธิ์นั้นถูกลบไปด้วย GR Lab ขอสิทธิ์เข้าถึงแบบเต็มเพื่อดูแลอัลบั้มของแอป และบน simulator ของ iOS 26.3 การใช้ `simctl privacy grant photos` เพียงอย่างเดียวไม่ได้ทำให้ iOS หยุดถาม เพราะสิทธิ์ที่บันทึกไว้มี `auth_version` เป็น 1 และ iOS จะถือว่าเป็นการเข้าถึงแบบเต็มก็ต่อเมื่อค่าเป็น 2 เท่านั้น ให้สิทธิ์และตั้งค่านี้ก่อนรันทุกครั้ง:

```sh
cd app
flutter build ios --simulator --debug --dart-define=GR_DEMO=true
xcrun simctl install booted build/ios/iphonesimulator/Runner.app
xcrun simctl privacy booted grant photos io.jeph.grlab.dev
sqlite3 "$(xcrun simctl getenv booted HOME)/Library/TCC/TCC.db" \
  "UPDATE access SET auth_version = 2 WHERE service = 'kTCCServicePhotos' AND client = 'io.jeph.grlab.dev'"
flutter test integration_test --dart-define=GR_DEMO=true -d <simulator>
```

### ล็อกดีบัก

GR Lab จะเก็บล็อกดีบักขณะที่ การตั้งค่า > เปิดใช้ล็อกดีบัก เปิดอยู่ ได้แก่ ทุกอย่างที่แอปส่งไปยังกล้องและรับจากกล้อง (การสแกน การอ่าน การเขียน และการแจ้งเตือนของบลูทูธ คำขอและคำตอบ HTTP ทุกรายการ ข้อความ WebSocket ขนาดเฟรมของไลฟ์วิว และขั้นตอนการเข้าร่วม Wi-Fi) ทุกบรรทัดที่แอปพิมพ์ออกมา ข้อผิดพลาดที่ไม่ถูกดักจับ และบรรทัดจากโค้ด Wi-Fi แบบเนทีฟ การตั้งค่านี้เปิดเป็นค่าเริ่มต้นใน `dev` และปิดใน `prod` ขณะที่ปิดอยู่จะไม่มีการบันทึกล็อกใดๆ แม้แต่ใน logcat หรือคอนโซล โดยมีข้อยกเว้นข้อเดียว คือเอนจินของ Flutter ยังคงรายงานข้อผิดพลาดที่ไม่ถูกดักจับไปที่นั่นเอง การแครชจึงยังมองเห็นได้ การตั้งค่า > ล็อกดีบัก จะส่งออกล็อกผ่านแผ่นแชร์ของระบบเป็นไฟล์ JSON Lines แล้วล้างล็อก ล็อกเก็บข้อมูลได้ประมาณ 50 MB และมีรหัสผ่าน Wi-Fi ของกล้องอยู่ด้วย

### TestFlight

```sh
tool/testflight.sh       # บิลด์แอป iOS แบบ prod แล้วอัปโหลดไปยัง TestFlight
```

สคริปต์นี้บิลด์ flavor `prod` โดยใช้เวลาที่อัปโหลดเป็นหมายเลขบิลด์ แล้วส่งไปยัง App Store Connect ซึ่งบิลด์จะปรากฏใน TestFlight เมื่อประมวลผลเสร็จ ผู้ทดสอบภายในติดตั้งได้จากแอป TestFlight โดยไม่ต้องใช้สาย Xcode จะเซ็นและอัปโหลดบิลด์ด้วยคีย์ API ของ App Store Connect ดังนั้นสิ่งที่ต้องตั้งค่าบน Mac คือไฟล์ `AuthKey_<key id>.p8` ของคีย์ใน `~/.appstoreconnect/private_keys` และ `ASC_KEY_ID` กับ `ASC_ISSUER_ID` ใน `~/.appstoreconnect/gr-lab.env` คีย์ต้องมีบทบาท Admin เพราะ Apple ไม่อนุญาตให้คีย์ระดับ App Manager ใช้ใบรับรองสำหรับเผยแพร่ของทีม ไฟล์ archive จะถูกบิลด์โดยไม่เซ็น แล้วเซ็นสำหรับ App Store ตอนส่งออก (`app/ios/ExportOptions.plist`) เพราะการเซ็นตัว archive เองต้องมีอุปกรณ์ทดสอบที่ลงทะเบียนไว้ในทีม

## การมีส่วนร่วม

ยินดีรับรายงานข้อบกพร่องและ pull request ข้อบกพร่องส่วนใหญ่จะปรากฏเฉพาะบนฮาร์ดแวร์จริง ดังนั้นเมื่อคุณ[เปิด issue](https://github.com/jeph/gr-lab/issues) โปรดระบุรุ่นกล้องและเวอร์ชันเฟิร์มแวร์ รุ่นโทรศัพท์และเวอร์ชัน Android หรือ iOS และสิ่งที่คุณทำ ล็อกดีบักที่ส่งออกมา (การตั้งค่า, ล็อกดีบัก, ส่งออกล็อก) มักแสดงให้เห็นว่าเกิดอะไรขึ้น แต่ในล็อกมีหมายเลขซีเรียลและรหัสผ่าน Wi-Fi ของกล้องคุณอยู่ จึงควรแนบมาเฉพาะเมื่อคุณสะดวกใจที่จะแชร์ข้อมูลเหล่านี้

ก่อนส่งการเปลี่ยนแปลง ให้รัน `tool/check.sh` โดยต้องผ่านการตรวจสอบทุกข้อ [`AGENTS.md`](../../AGENTS.md) อธิบายการจัดระเบียบโค้ดและกฎที่โค้ดต้องปฏิบัติตาม

อย่ารายงานช่องโหว่ด้านความปลอดภัยที่สงสัยว่ามีผ่าน issue สาธารณะ ให้ทำตาม[นโยบายความปลอดภัย](../../.github/SECURITY.md)เพื่อส่งรายงานช่องโหว่แบบส่วนตัว
